# Game audit — 2026-09-21

The deployed compatibility alert and oversized canvas were reproduced in Chromium
before editing. Baseline: 49 Lua tests, native UI/pixel smoke, native package and
web build passed. The tests did not cover browser layout or restricted storage.

## Fixed findings

| Priority | Trigger and effect | Fix location |
| --- | --- | --- |
| P1 | IndexedDB population fails: love.js keeps its `IDBFS_sync` dependency pending forever, so the game never starts and the localStorage backup is ignored. | `web_template/storage-bridge.js`: restore the independent backup and allow the initial runtime callback to finish using MEMFS. |
| P1 | A small/high-DPI viewport is below the original 720×600 logical minimum: the rendered scene clips even when the HTML canvas fits, and touch coordinates disagree with visible controls. | `conf.lua`: allow viewport-sized windows; `web_template/index.html`: resize through the runtime with physical pixel dimensions. |
| P2 | Browser boot always alerts because the game declares 11.5 while the bundled runtime is 11.4. | `conf.lua`: declare the supported 11.4 API version. Native 11.5 remains supported and tested. |
| P2 | A fixed 1080×900 canvas overflows the page; integer-only scaling and source-image margins leave the desk small. | `web_template/theme/love.css`, `src/UI.lua`, `main.lua`: fit the viewport, scale visible scene bounds, crop unused margins, preserve aspect ratio, use the same transform for input. |
| P2 | The market's studio-link hitbox covers both page arrows, making titles 7–9 inaccessible with mouse/touch. | `src/Overlay.lua`: give pagination and the link separate hit regions. |
| P2 | Fullscreen uses obsolete browser method names and bypasses runtime resize coordination. | `web_template/index.html`: modern wrapper fullscreen and a shared F11/button path. |
| P2 | Keyboard-only players can open the market but cannot choose a master or most controls. | `src/UI.lua`, `main.lua`: Tab/Shift+Tab focus, visible focus outline and Enter activation. |
| P3 | `openURL` returns false without throwing: the application treats it as success and gives no fallback. | `src/App.lua`: inspect both protected-call and API results. |
| P3 | A screenshot directory containing an apostrophe breaks the developer harness shell command. | `harness.lua`: quote POSIX directory arguments correctly. |

## Verification

- 51 deterministic Lua tests pass, including all nine orders, business progression,
  multi-target verification, viewport fitting and failed-link feedback.
- Native smoke exercises rendered hit regions, typing, keyboard selection,
  pagination, media swaps, verification, payments, hardware and audio.
- 385,906 static artwork pixels and all three target-bulb sprites still match the
  original bitmap; the source art is unchanged.
- Three real browser playthroughs pass: 1440×900 desktop, 844×390 landscape touch,
  and 390×844 portrait touch. Both touch runs use device pixel ratio 2.
- Each browser run buys a master, copies through three swaps, automatically
  verifies, receives $70, then reloads and resaves the restored business state.
- Fullscreen enter/exit and live resizing to 2805×1854, 1024×768 and 320×568 pass.
- Browser startup and restoration of a $170/two-delivery save pass with
  IndexedDB deliberately disabled.
- Save-bridge regressions cover normal and failed IndexedDB population, atomic
  rename mirroring, and localStorage quota failure.
- Native scene screenshots cover desk, market, hardware, order info, configuration,
  copying, swaps, protection errors, calibration, completion, multiple targets and
  credits. Browser screenshots live in `screenshots/audit-web/`.
- Native packaging verifies archive CRCs and byte-for-byte source equality.
- GitHub Pages now runs the Lua, bridge and browser tests before deploying.

## Review and limits

Claude performed an independent read-only code audit and a final diff review.
Its initial claims about broken Emscripten `os.rename`, a verification-loop overrun,
UTF-8 save corruption and invalid two-page pagination did not reproduce and were
rejected: the current implementations are correct for this runtime and catalog.
Final Claude review: **PASS**, with no concrete reproducible bugs found in the diff.
The first attempt to resume the reviewer hit a session-ID error; a fresh stateless
Claude review completed successfully.

`npm audit` reports the old build packager's transitive `uuid` dependency. Its
advisory concerns v3/v5/v6 calls with caller-provided buffers; this packager only
calls v4 with no buffer, and uuid is not shipped in the browser runtime. No exposed
vulnerable call was found; replacing the old package with a modern uuid API would
break the upstream packager without an adapter.

Browser validation uses Chromium with desktop and touch-device emulation, not
physical iOS/Android devices. The wide original interface keeps its aspect ratio;
portrait screens therefore retain space around the fitted desk. Gamepad support
is not implemented by this project (`t.modules.joystick = false`).
